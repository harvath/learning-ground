What Lean did differently

If the logic is decades old, what's new? Four things, none of them a theorem: a proof assistant that is a real programming language, one library instead of many, modern tooling, and an organization built to maintain it.

The 30-second version

Lean's logic is close to Coq's; a logician would call them cousins. What Lean changed is everything around the logic — the things lesson 3 identified as missing. It was designed by a software-tools person as a programming language first. Its community put all its mathematics into a single, unified library. Its editor experience is what a modern developer expects. And in 2023 it got a funded, full-time engineering organization. Each of those is unglamorous. Together they produced the first proof assistant with an ecosystem.

Where it came from

Leonardo de Moura was not a type theorist by trade. Before Lean he was the main architect of Z3, Microsoft Research's SMT solver — a tool that automatically decides whether a logical formula can be satisfied, used inside countless program-analysis and verification tools.[1][2] He came to proof assistants as someone who builds fast, widely-used automated reasoning software. His stated motive: "We built Lean because we care about software development."[3]

1. A proof assistant that is a real programming language

The Lean 4 paper's first sentence: "Lean 4 is a reimplementation of the Lean interactive theorem prover (ITP) in Lean itself."[6] That's the key design decision, and it has two consequences.

Users can extend the system in the language they already use. In Lean 3, large parts of the system could only be changed by editing its C++ source. In Lean 4, the paper says, "users can modify and extend the parser, elaborator, tactics, decision procedures, pretty printer, and code generator" — all in Lean.[6] (The elaborator is the stage that turns the convenient code you write into the fully explicit form the kernel checks.) So a mathematician who needs a new tactic, or notation that matches how their field writes things on a blackboard, writes it as an ordinary library — no compiler hacking, no waiting for the core team. The proof automation people rely on is mostly community-written this way.

It's fast enough to build real software in. Lean 4 compiles to C, and uses a memory-management scheme the authors call "functional but in-place": code is written in a pure functional style, but when a value has no other references the compiled program updates it in place rather than copying.[6] The proof that this is practical is Lean itself — its compiler, build tool, and editor server are written in Lean.[7]

For the programs-you-want-verified use case, this closes a gap older systems had: the code you prove things about and the code you run are the same code, not a model of it in a separate language.

2. One library: mathlib

mathlib is "a community-driven effort to build a unified library of mathematics formalized in the Lean proof assistant."[8] The important word is unified. Where earlier ecosystems had many separate libraries (lesson 3), mathlib is one repository with one set of definitions, where — as one contributor put it — "all the pieces work with all the other pieces."[3] In software terms it's a monorepo with strict review and a single definition of every concept: if you prove something about groups, everyone else's theorems about groups apply to your object automatically.

The effect is compounding. Each new formalization starts from everything already there, and what it adds becomes available to the next. As of this writing mathlib holds 296,355 theorems and 142,131 definitions from 772 contributors.[9] as of Nov 25, 2026 In October 2020 the figure was 38,315 theorems.[3]

One measure of the community's capacity: when Lean 4 broke compatibility with Lean 3, volunteers ported the entire library — on the order of a million lines — in about ten months, finishing in July 2023.[10]

3. Tooling a developer would recognize

Lean ships with a build system and package manager (Lake), a VS Code extension whose side panel shows the live proof state as you type (the goal view from lesson 1), a zero-install browser playground, and search engines for the library — Loogle lets you search hundreds of thousands of theorems by the shape of their statement.[11] None of this is conceptually deep. All of it lowers the cost of getting started from "weeks" to "an afternoon", which decides who shows up.

4. An organization

The Lean FRO was founded in July 2023 by de Moura and Sebastian Ullrich (co-author of Lean 4) as a non-profit. A Focused Research Organization is a startup-shaped non-profit: a full-time engineering team funded by philanthropy to build something too engineering-heavy for a university lab and not profitable enough for a company. Its backers include the Simons and Sloan foundations and, more recently, AI companies and Amazon.[4][12] In July 2025 one donor gave $10M, split between the FRO and mathlib.[13]

The point: a proof assistant is infrastructure, and infrastructure maintained by a few academics in their spare time doesn't get release engineering, documentation, or performance work. Lean now has about twenty people whose job that is.[14]

keep it honest Lean is not more "powerful" than its predecessors in any logical sense, and it did not win on a technical knockout. Rocq and Isabelle are mature, actively used, and behind most of the verified software in lesson 3. Lean's lead is specifically in mathematics and, lately, in AI — and it's a lead in ecosystem and momentum. In 2025 Lean received the ACM SIGPLAN Programming Languages Software Award, with a citation noting it "has become the de facto choice for AI-based systems of mathematical reasoning."[15] "De facto" is the right phrase: a network effect, not a proof of superiority.

Check it sticks

① Someone says "Lean is a breakthrough in logic." Correct them: what is actually new about Lean?

The logic is essentially the same family as Coq's, decades old. What's new is around it: (1) Lean 4 is a real, compiled programming language written in itself, so users extend the system in Lean; (2) mathlib, a single unified library where work compounds; (3) modern tooling; (4) a funded full-time organization, the Lean FRO. Engineering and community, not a new theory.

② Why does it matter that Lean 4 is implemented in Lean?

Self-hosting makes the system extensible by its own community and demonstrates the language is fast enough for real software. It changes nothing about the logic, and the kernel is still the trusted part.

③ What's the main advantage of mathlib being one unified library rather than many separate ones?

One definition of each concept means everyone's theorems interoperate. (It does not compile fast — a monolith that size is slow to build and painful when things change underneath it; that's the price.)

ask the teacher So by 2020 the pieces existed: a good tool, a growing library, a small enthusiastic community. What it didn't have yet was a reason for anyone outside that community to care. Lesson 6 is how it got one. First, lesson 5 steps sideways: proof assistants aren't the only way to check software, and you'll hear TLA+, Dafny, and others named in the same breath as Lean.
