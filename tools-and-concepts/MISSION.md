# Mission: Tools & Concepts — a field notebook of things worth knowing about

## Why
The user (a software engineer) keeps running into tools, languages, and ideas that people are talking about — Lean was the first one named — and wants to actually understand each one: what it is, the concept underneath it, what is new about it, why it is getting attention now, and what changed in the surrounding ecosystem to make it possible. None of these deserves a full course of its own on the level of `japanese-mythology/` or `software-defined-vehicles/`. This course is the umbrella that holds them: one **set** of a few lessons per tool or concept.

## Shape
- The course is open-ended. It has no fixed syllabus; sets are added when the user names a new tool or concept.
- One set = one tool/concept = roughly 3–6 short lessons, living in `lessons/<set-slug>/`.
- Sets are independent of each other. A set may link to another when the ideas really connect, but never depends on it.

## Success looks like (per set)
- Can say in two sentences what the thing is, to another engineer, without hand-waving
- Can explain the one core idea underneath it well enough to predict how it behaves
- Knows what came before, and can name what this thing does differently
- Can explain why people are talking about it *now* — the specific events and the ecosystem change, with dates
- Knows the honest limits and the open questions, so the hype can be discounted correctly
- Knows where to go to try it, if they decide to

## Constraints
- Literacy first, not mastery. A set gets the user to "I understand this and could start using it", not to proficiency. Hands-on depth is a follow-up the user can ask for.
- Every factual claim about the world (dates, numbers, who did what) is cited to a checkable source and dated. These topics move fast.
- Plain-language working definition first; formal definitions and comparisons second. Every technical term is glossed inline at first use.
- One lesson, one win. Short.

## Out of scope
- Full tutorials or reference documentation for any tool — link to the official ones instead
- Topics big enough to deserve their own course; those get their own top-level directory
